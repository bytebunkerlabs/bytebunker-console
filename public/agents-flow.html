How agents run

A goal goes to a master that plans and a team of helpers that do the work, on a machine of their own.

modelsYour model servers

Engines dgx-serve runs, on a Spark, an NVIDIA box, a Windows PC or a Mac. They serve models and nothing else: no agent code runs there.

controlByteBunker

Starts each goal on the worker over SSH, follows it, stops it when asked, and keeps the record: the transcript, the tokens, the jobs it filed.

agentsThe worker

A separate machine. The master plans; each helper runs in a fresh container with no network unless the master grants it.

  1. You give a goal: on the Agents screen, with bb agents "goal", or as a scheduled job.
  2. ByteBunker starts it on the worker over SSH and streams what the master says as it works. Closing the app does not stop it; Stop does.
  3. The master plans and hands steps to helpers, each in a fresh container. A helper gets the network only when the master grants it, for that helper alone.
  4. Helpers reach models only through the worker's proxy, which adds the keys. No key is ever inside a container.
  5. Skeptics check each helper's answer before the master uses it.
  6. The master writes the answer. ByteBunker records it with the tokens it took; work that should happen again can come back as a job.

The worker is never the machine that serves the models, and never the one ByteBunker runs on: a goal that goes wrong stays inside its containers on the worker.
